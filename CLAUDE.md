# CLAUDE.md — веб-прототип Backpack RPG

Отвечать по-русски, коротко и практично. Автор — Дмитрий, Unity-разработчик и геймдизайнер. Веб он знает слабо, поэтому объяснять простыми словами.

## Что это
Одностраничный прототип кооп-боя Backpack RPG для плейтестов с друзьями в Discord. Проверяем только механики, визуал не важен.
Целевой экран — горизонтальный монитор (1920×1080, есть компактный режим до 1366×768), вид сверху. Мобильные не поддерживаем.
Опубликован на GitHub Pages: сайт собирается из ВСЕХ веток (`.github/workflows/pages.yml` → `tools/build-pages.sh`). `main` — корень https://eclipse130300.github.io/backpack-proto/, любая ветка X — папка `/x/` (имя маленькими буквами, не a-z0-9- → «-»), список — `versions.html`. Пуш в другую ветку запускает `branch-push.yml`, тот — пересборку от `main` (окружение github-pages пускает только main).

## Версии (вариации игры)
- Каждая вариация механики («мердж», «больше оружия»…) — отдельная ветка от `main` со своей ссылкой. Дмитрий говорит «в merge сделай…» — правим и пушим только эту ветку. Если ветка не названа — спросить, в какую версию.
- Понравилось → влить в `main` (по его слову). Не понравилось → удалить ветку (по его слову). `v1-old` — замороженная игра до мерджа (18.10), не трогать.
- `js/version.js`: сборка вписывает `window.BP_BRANCH`; для не-main версий ключи `localStorage` `bprpg-…` получают приставку `bprpg@<ветка>-` (кроме `bprpg-name`), комнаты PeerJS — тоже. Новые ключи хранилища называть `bprpg-…`, тогда они изолируются сами.
- Новые ветки создавать ТОЛЬКО когда Дмитрий прямо попросит (каждая ветка = лишняя ссылка, не мусорить). Баланс и прочие правки — коммитом прямо в нужную версию (по умолчанию `main`), точка отката — тег.
- Имена веток `css`, `js`, `tools` нельзя (заняты папками).

Источник правды по геймдизайну — не этот репозиторий, а Google Doc «GDD AI», `Docs/GameContext.md` в Unity-проекте BackpackRPG и Miro.
Прототип реализует то, что там решено, плюс эксперименты под переключателями. Если правка в прототипе противоречит решённому — спросить.

## Устройство (без сборки, без фреймворков)
- `index.html` подключает обычные `<script>` (не ES-модули), чтобы игра открывалась и двойным кликом через `file://`. Всё лежит в глобальном `window.BP`.
- `config.js` (`window.GAME_CONFIG`) — все данные: rules, tests (переключатели), shapes, cards, weapons, heroes, enemies, questConditions/questRewards, encounters. Дмитрий правит его сам на github.com, поэтому комментарии в нём обязательны и должны быть актуальны.
- `js/hex.js` — геометрия поля 6×2, хексы ровной стороной к героям (flat-top): row 0 передний (внизу), row 1 задний строго за ним в той же колонке; колонки 0, 2, 4 ближе к героям, 1, 3, 5 сдвинуты на полхекса назад. 6 направлений: ↗ ↑ ↖ ↙ ↓ ↘.
- `js/cards.js` — текст карты (генерируется из effects), проверка цели, расчёт урона и крита (с превью), мердж и его стоимость (`mergeCost`), тип карты для цвета (`kind`).
- `js/deck.js` — колоды: сборка на бой (обычный режим и общая колода `tests.sharedDeck`), добор, сброс. У карты `owner` (id героя) или `shared: true`.
- `js/weak.js` — слабые удары оружия (`weapons.*.weakCard`, добивка до `minDeck`), заготовка «Слабый удар (любой)» в общей колоде, которая при доборе становится слабым ударом героя (`adapt`), эффект `sparks` (искры мага).
- `js/engine.js` — правила: забег, бой, ход игроков, фаза врагов (`enemyStep` по одному врагу), толчок с пересчётом целей (`reintent`), лог, итоги. Состояние — чистый JSON.
- `js/quests.js` — квест боя (`tests.fightQuest`): фаза `questPick` перед боем (3 варианта, голоса `questVote`, ничья — жребий, хост через `result.ms` шлёт `questStart`), прогресс, выдача одноразовой карты (`exhaust`, `retain`) герою, закрывшему условие.
- `js/net.js` — транспорт: PeerJS (WebRTC P2P через публичный сервер PeerJS, библиотека с jsDelivr) или BroadcastChannel (`?net=bc`, вкладки одного браузера, для отладки).
- `js/session.js` — роли local / host / client. Хост авторитетен: применяет действия через `BP.Engine.applyAction`, крутит фазу врагов и рассылает `publicState`. Клиент только шлёт действия.
- `js/ui-game.js` (отрисовка боя: поле, фишки героев, руки всех трёх героев внизу), `js/ui-drag.js` (перетаскивание и клик-выбор целей, мердж на карты союзника, поворот массовок ПКМ, призрачные хексы ✕ за краем, панель подсказок `#board-hint`, ромб мерджа на месте стоимости карт союзников, их обычная стоимость скрыта), `js/ui-fx.js` (цифры урона, тряска, стрелки намерений, мерцание целей врага, тултипы с обходом стрелок — по `state.fx`), `js/icons.js` (SVG-картинки карт и портреты), `js/ui-quest.js` (выбор квеста на месте рук, рулетка), `js/ui-deck.js` (окно «Колода»/«Сброс»), `js/ui-settings.js` (модалка настроек: цветные группы, пояснения по клику на «i», без ховер-подсказок), `js/ui.js` (меню, лобби, итоги, кнопки).
- `cards.html` — страница «Карты» (каталог + симулятор), те же скрипты, что игра: `js/catalog.js` (каталог, группировки, фильтры, панель карты; `BOARD_URL` — ссылка на доску заявок), `js/catalog-sim.js` (вкладка симулятора, результаты в `localStorage` `bprpg-sim-results`), `js/sim-worker.js` (фоновый поток на http/https; на `file://` считает в основном потоке).
- `js/sim.js` — боты smart / medium / sloppy и сводка (`BP.Sim.runOnce`, `summarize`, `verdict`): общий код для страницы и `tools/balance-sim.js` (консоль, Node). По картам считает «была в руке → сыграна» (`playRate`).
- Карты по заявкам Дмитрия помечаются `isNew: true` и `added: "дата"` — значок 🆕 в каталоге. Снимать `isNew`, когда Дмитрий скажет, что карта больше не новая.
- Настройки хоста (⚙) сохраняются в `localStorage` (`bprpg-config-override`) и перекрывают `config.js`. Об этом в лобби висит предупреждение. При смене `version` в `config.js` старые настройки сбрасываются — повышать `version`, когда меняется структура конфига.

## Правила работы
1. Не тащить сборщики, npm-зависимости, фреймворки и ES-модули: проект должен оставаться «залил файлы — работает».
2. Новые механики — данными в `config.js` и, где это эксперимент, под переключателем в `tests`. Новый тип эффекта: обработать в `engine.js`, описать в `cards.js` → `text()` и в комментарии конфига.
3. Менять одно правило за раз, минимально. Файлы держать небольшими (ориентир до ~300 строк, `engine.js` уже на пределе — новое выносить в отдельный файл).
4. Действия игрока проходят только через `applyAction` на хосте, UI состояние напрямую не меняет.
5. Если меняется то, что видит или делает игрок, — обновить `README.md`.
6. Работать только в этом репозитории, другие репозитории Дмитрия не трогать. Пушить после проверки (любой пуш — сразу выкладка своей версии).

## Как проверять
- Локально: `python3 -m http.server` в корне репозитория и Playwright (Chromium предустановлен). CDN PeerJS из облачного контейнера обычно недоступен — его запросы блокировать (`route('**/cdn.jsdelivr.net/**', abort)`), локальная игра работает и без него.
- Сеть: две-три вкладки в одном контексте браузера с `?net=bc` (хост создаёт комнату, остальные входят по коду) — проверяется вся логика хоста и клиента. Настоящий PeerJS проверяет Дмитрий у себя.
- Баланс: движок запускается в Node без DOM (`global.window = global; require` файлов `config.js`, `hex.js`, `cards.js`, `weak.js`, `deck.js`, `engine.js`, `quests.js`, `sim.js`) — удобно гонять бота на сотни забегов (`node tools/balance-sim.js 100 smart --seed 1`).
- Страница «Карты»: открыть `cards.html` и `cards.html#sim`, прогнать 30 забегов sloppy — без ошибок в консоли.
- После правок смотреть скриншоты 1920×1080 и 1366×768 и проверять, что в консоли нет ошибок.

## Заглушки (не решения по игре — не выдавать за решённое)
Смерть героя (встаёт к след. бою с `reviveHp`), единственный дебафф «Проклятие» (статусы отложены), 
крит по счётчику только у карт оружия, враги сверху / герои снизу, условные герои Милишник / Маг / Стрелок.
Решено и учтено: толчок меняет цель врага по новому коридору (провокация сильнее), прикрытие пересчитывается; щит — отдельный тип снаряжения (`weapons.*.kind: "shield"`), пока только у милишника; мердж решён, бонус живёт до конца боя (переживает сброс); мили (герои и враги) бьют только открытых — задний закрыт, если занята клетка прямо перед ним; враги не шагают; задачи пати убраны (17.10) — их место занял квест боя; добор ровно `rules.drawPerTurn` (4) карт за ход, не «до N» (несгоревшая квестовая — пятая); классов нет — колода героя = карты оружия + кооп-карты + слабые удары до минимума.
Эксперименты (не решено): слабые удары от оружия (меч 3 мили / лук 2 дальний / посох «Искры»), выбор квеста голосованием, «Единение» только как награда квеста.
